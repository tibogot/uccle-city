**Rule.** A warm-up that is only allowed in one lighting state (here: the lamp-shadow warm-up, which points both shadow lamps at the city from 350 m up for a frame and so runs only while the lamps are dark) needs a path for the OTHER state too, or a start in that state never warms. At night the lamps' passes are warmed in place: no light is moved, added or dimmed. One stand-in per (material, geometry layout) is drawn with a zero-scale matrix (no pixel written) on the lamps' own layer, both lamp maps forced to one full render, kept until both passes really drew it. Under the play loader the spawn ring's keys are warmed (the loader waits for them), the rest after play one key every 12 frames (one 1-3 ms depth-only build per lamp).

**Why.** viewer/nightLights/cityNight.js called its warm-up (warmShadows) from the by-day branch only (`lastScale <= 0`). A police game started at night (?game=police&time=night) never ran it: warmPending() never fell (~750 casters queued, tile by tile), the play loader's `settled` waited for it to its 70 s limit, a night start took ~150 s, and every caster's lamp pass was then built on screen as lamps came near (2026-11-28, foundation too). The casters are many but their keys are few: the node build and the pipeline are shared by every mesh with the same material and geometry layout, so a stand-in per key warms them all (279 keys for the police spawn's ~750 casters).

**Lights.** Fixed light count (rule fixed-light-count): the two shadowed spots exist from the boot and the night warm only renders their maps; a dark lamp's map is rendered too (its pass is the one the night will use). ?nightwarm=old: the by-day path only, as before; ?nighthold=old: the loader does not wait (the A/B).
