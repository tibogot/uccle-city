**Rule.** ONE switch for every sound: the speaker button (viewer/audio/soundGate.js) gates every AudioContext the viewer makes (the city, the two-wheelers, the falcon, the games' cues, the police siren), OFF by default, remembered per browser; a module that makes a context imports the gate and makes it only while the sound is on; no mode keeps a second on / off switch (no key, URL switch, menu tick or panel toggle). A system that simulates something audible feeds the sound engine from its live state (positions, speeds, stops, clock, weather), never from a fixed recording; its control updates run at the engine's control rate, in pools fixed at start (no object, array, closure or string made per update, one shape per pool so the engine's loops stay monomorphic), the main-thread cost under 0.1 ms a frame; banks and impulse responses are baked off the main thread, nothing bakes on a frame; a node a voice stops using is disconnected from its inputs too.
