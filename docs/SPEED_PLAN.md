# Speed plan: where development time goes and how to cut it

Measured read-only on 2026-11-20. The owner asked: "find the way that will make us work faster."

## Where the time goes

**The merge gate.**
- 47 rows, run one after another: 34.5 min of median row time per run, plus flaky reruns.
- Seven rows take 77 %: drivecheck 326 s, ground 310, trafpark 259, roads 140, tramrails 118, markings 101, streetprops 99.

**Duplicate work in every gate run.**
- The road stage is built ~579 times for 120 distinct tiles (4.8×).
- The full worker build ~300 times for 120 tiles (2.5×), all with the same entry.

**Rows run that a change never touches.**
- Over the last 15 merges: 31,094 s with full runs vs 16,524 s if only the needed rows had run (-47 %).
- The 7 merges that didn't touch the tile core needed ~4-6 min, not 34.
- 14 rows run on every merge only because they read features.js / main.js as text.

**Flaky timing rows.**
- stutter2 and mdrawcull assert the max of one wall-time sample.
- drivecheck hits the fixed 600 s timeout.
- 4 of 13 logged runs failed on timing alone.

**Merge conflicts.** Over 40 merges, both sides changed:

| File | Merges |
|---|---|
| mergeGate.mjs | 23 |
| QUALITY_RULES.md | 21 |
| features.js | 20 |
| CENSUS.md | 15 |
| main.js | 15 |

Also: 5 rule renumberings, and 23 hand commits that only rebuild the worker bundle.

**Browser checks.**
- One Chrome, by hand, queued.
- 39 debug/ scripts already expose run / ab / check functions; about 12 of the 20 browser checks can be scripted today.
- Nothing launches headless Chrome yet.

**Old switches.** features.js has 196 `old(...)` rows, all under 3 weeks old.

## Speed-ups, ranked by time saved per merge
1. **Run only the rows a change needs**, found by a dependency tracer, plus memoising passing rows by content hash: 34 → ~18 min on average, and ~1-4 min on non-core merges. A full run stays as the nightly safety net.
2. **No more sync conflicts:**
   - one file per gate row (`tools/audit/gate.d/<name>.mjs`);
   - one file per rule (`docs/rules/<slug>.md`, by name, no numbers) and per census class;
   - `.gitattributes merge=union` for features.js, one row per line.
   - Saves ~20-35 min per avoided sync.
3. **A `meta` row** for the features-row / no-light / no-DynamicDrawUsage text checks, so 14 rows stop running on every merge: 3-4 min on small merges.
4. **One tile build, many probes**, plus a content-hashed cross-run tile cache: 8-12 min on core runs, ~0 when the core didn't change.
5. **A parallel runner with a memory budget** (4 heavy slots + a light pool; trafpark / tlights on worker jobs): 8-10 min.
6. **Robust timing rows** (best of N + a calibration ratio; timing rows run alone first; a timeout per row): 3-5 min plus agent turns.
7. **A headless browser runner** (tools/browser/run.mjs: serve.mjs + Chrome --headless=new with WebGPU over CDP; a GPU lock for perf rows): 10-30 min of browser turns per merge, and browser checks run in parallel.
8. **Bundle freshness:** auto-rebuild the worker bundle in a one-command merge script (merge, rebuild, needed rows, push, worktree cleanup): 2-5 min plus no stale-bundle risk.

**Old-switch policy:** a switch lives until the owner accepts the feature, or 7 days / 3 merges. Then the old path is deleted and its "old fails" proof is frozen as a fixture.

## Done in claude/speed1 (jobs 1, 2, 3, 9)

See docs/WORKFLOW.md for the how-to.

- **gate-split:**
  - one file per row: `tools/audit/gate.d/<name>.mjs`, and `gate.d/browser/<name>.mjs` for the browser rows;
  - `mergeGate.mjs` loads the folder: timing rows first, then by name;
  - a timeout per row (drivecheck 1800 s, default 600).
- **rules-split:**
  - one file per rule: `docs/rules/<slug>.md`; rules 1-48 keep `number:` for history, new rules get no number;
  - one file per census class: `docs/census/<class>.md`;
  - `docs/QUALITY_RULES.md` and `docs/CENSUS.md` are generated by `tools/docs/rulesIndex.mjs`;
  - `viewer/features.js merge=union`: the 5 multi-line rows are now one line each, and the dev panel groups rows by `sub`.
- **meta row** (`tools/audit/metaGate.mjs`):
  - runs every row's `meta` (features rows, main.js wiring, no light, no DynamicDrawUsage), so 17 rows lost those
    checks: dent, tyremarks, engine, citysound, motofeel, heap, stutter, stutter2, mdrawcull, policerear, xmas, lycee,
    tlights, bushes, hedges, birds, jitter;
  - checks features.js: one row per line, no key twice (`carmerge` is knowingly two rows);
  - checks the two generated indexes;
  - checks that every viewer/ debug/ tools/ module parses and links (esbuild, about 800 files, about 1 s);
  - `skyctl` keeps its features-vs-panel check, because that check is its test.
- **merge script** `tools/merge.mjs` does merge, bundle, rows (auto / full / list), push and worktree cleanup.
  - `auto` used a static import crawl plus the repo paths named in the scripts. The tracer (job 4, claude/speed2)
    replaced it.

## Done in claude/speed2 (jobs 4, 5, 6, 7; job 8 measured only)

See docs/WORKFLOW.md "Memo and --changed" and "Timing rows" for the how-to.

- **Dependency tracer** (`tools/gate/trace.mjs`):
  - an `--import` hook loaded through `NODE_OPTIONS`, so it reaches the row's node children (runTiles) and worker
    threads (roadbends);
  - it records the modules loaded (a load hook), the files read and the directories listed, plus the files written
    (the row's outputs, left out) and each process's peak memory;
  - into `.cache/gate/deps/<row>.json`. `tools/gate/deps.mjs` prefers it over the static crawl.
  - `viewer/main.js` is now read by 2 rows (meta, motion), not 14; `viewer/features.js` by 3. A tile-core file
    (heightmap.js, roadBuild.js) is read by 23 rows.
- **Row memo + `--changed`** (`tools/gate/memo.mjs`, `tools/gate/select.mjs`):
  - the memo key = node version + the row's gate.d file + the content hash of every traced file + the names in every
    listed directory (hashes cached by size + mtime);
  - `--changed [--base REF]` runs meta plus the rows a changed file touches. `tools/merge.mjs auto` uses it against the
    pre-merge commit. `--full` turns the memo off. Every skip is printed with its reason.
- **Timing robustness** (`tools/gate/timing.mjs`, rule timing-rows, checked by `meta`):
  - budgets are multiplied by `k`, a calibration loop timed before and after in the same process; a run is discarded
    while the two differ by more than 15 %;
  - worst-step checks use each step's best of 5 (`cleanSteps`) or the best of 3;
  - mdrawcull's sort cost is now the best of 150 short windows, not of 15 windows of 300 frames;
  - engine's idle-garbage sample re-warms when the optimizing compiler ran late;
  - 8 timing rows (carhit, citysound, engine, mdrawcull, orbitcam, stutter, stutter2, tyremarks) run alone, first.
- **Parallel runner** (`tools/audit/mergeGate.mjs`):
  - the other rows run in a pool, longest first, within a CPU budget (the logical cores) and a memory budget (60 % of
    RAM, and 1 GB must stay free on the machine);
  - at most 3 heavy rows at once. Costs come from the traces: tile rows peak at 1.6-3.0 GB;
  - timeouts are doubled in the pool, and a timeout kills the whole process tree;
  - the table keeps the rows' order. It warns when one row writes a file another reads (none today).
  - `trafpark` and `tlights` now use runTiles (`--jobs 4`): tlights 575 s -> 121 s; trafpark from a 600 s timeout to
    226 s.

## Job 8 (tile cache): done in claude/tilecache

See docs/WORKFLOW.md "Tile cache" for the how-to, docs/rules/tile-cache.md for the rule.

- **What is cached:** the tile worker's whole build in node (`viewer/tileData.js` `buildTileData`), through
  `tools/gate/tileBuild.mjs` `tileData(entry, base)`. Wired: drivecheck, moverground, ground, gardenlanes,
  railcorridor, colliders, balconies, zfight, motofeel, deckrails, deckjoins (driveCheck.mjs, colliderAudit.mjs,
  census/railCorridor.mjs, census/moverGround.mjs, census/lib_mesh.mjs `buildTile`, roadfix/tile.mjs `buildTile`,
  moto/feelTest.mjs). They share one entry (the boot3 default): one build of a tile serves them all.
- **Key** (`tools/gate/tileCache.mjs`): the import closure of `viewer/tileWorker.js` (the bundle's inputs; `meta`
  checks it against esbuild's metafile), the canonical entry (keepNet out: it only adds), node version,
  `location.search`, the OffscreenCanvas stand-in's behaviour, and every file the build fetched / read / listed /
  tested, recorded while it built and re-hashed at each lookup (the last 8 input sets per entry).
- **Value:** plain data only (v8 structured clone, deflated level 1: a 45-60 MB tile is 12-15 MB; 120 tiles 1.1 GB).
  keepNet's live objects are not plain: `deckRings`, `net.streetModel.segments` and `hm` (`Heightmap.from`) are kept;
  any other `net.*` throws.
- **Safety:** atomic temp + rename; a per-tile build lock (the rows walk the tiles in the same order: without it they
  all built A5 together); no store when an input changed mid-build or the disk has < 10 GB free; LRU cap 4 GB
  (`TILE_CACHE_MB`); `--no-tile-cache` / `TILE_CACHE=0`; `TILE_CACHE=verify`.
- **Checks:** the `tilecache` row (20 mechanism checks on a synthetic build + I6 / H6 / E9 cached == fresh byte for
  byte, canonical sha256 with wall-time fields left out); `meta` (code key covers the bundle). Every wired row's output
  is the same with the cache off, cold and warm (2-tile runs of each, 2026-11-22; only colliders' ms column differs).
- **Not cached: the road stage** (`tools/road_audit/tile.mjs` `loadTile`, used by roads, streetlanes, gates, markings,
  markings2, tramrails, streetprops, trafpark, tlights, trafmix...). Its result holds closures (`net.locate`,
  `net.lineFit`, `prep`'s 11, `model.junctionAt`) over local state; rebuilding them is most of the stage. Caching it
  needs the data / rehydrate split inside roadBuild.js ("Next: the road stage" below), its own job.

**Hit cost:** 0.08-0.16 s a tile (read + sha1 + inflate + deserialize) against 4-10 s to build it.

## Branch conversion

The open branches made before claude/speed1 still edit the old single files: claude/ground, props, gates, trafmix and
kid. Convert each one once, in its own worktree:

```
git merge claude/foundation            # conflicts in mergeGate.mjs / QUALITY_RULES.md / CENSUS.md are expected: leave them
node tools/gate/convertBranch.mjs      # --dry-run first if you like
# resolve the real code conflicts it lists, then:
node tools/audit/mergeGate.mjs meta <your rows>
git commit
```

What `convertBranch.mjs` does, from the branch's own changes (its tip vs the fork point):

- **Gate rows.** Each CHECKS row the branch added becomes a `gate.d` file.
  - A changed row is merged field by field (fork point / branch / foundation). It keeps foundation's `meta`, `timeout`
    and `timing`. When both sides changed the same field it prints `CHECK row ...`.
  - A removed row is deleted.
  - Each BROWSER string becomes a `gate.d/browser` file.
  - `mergeGate.mjs` is set back to foundation's loader.
- **Rules.** Each rule the branch added gets a slug and no number. The script lists the files where the branch says
  "rule N", so they can be renamed. A changed numbered rule rewrites its own file. Both indexes are regenerated.
- **Census.** The branch's CENSUS.md lines are appended to the class file they sit under, inside a `convertBranch:`
  marker. Merge them by hand. The `meta` row fails while a marker is left.
- **features.js.** Conflict hunks are kept as a union of both sides, and multi-line rows are joined onto one line.

It stages what it writes. Tested on all five branches (a merge of claude/speed1 into a detached copy of each, then
aborted):

| branch | rows | rules |
|---|---|---|
| ground | moverground, movergroundunit + a browser row | rule 46 becomes a slug |
| gates | gates, gardenlanes new; drivecheck, ground, roads changed | rule 43 becomes a slug |
| props | props + a browser row | rule 44 becomes a slug |
| trafmix | trafmix + a browser row | rule 45 becomes a slug |
| kid | bike, kid, bmx + a browser row | its own rules 27 and 28, which clash with foundation's numbers, become slugs |

Real code conflicts are left to the branch: props has one in viewer/drive/driveMode.js, from the 23 foundation commits
it is behind.
